بهترین روش‌های ساخت REST API در لاراول که ای کاش زودتر می‌دانستم

API Resource، Form Request، نسخه‌بندی و خطاهای یکدست: چهار عادتی که توسعه و اعتماد به یک API لاراولی را ساده‌تر می‌کنند.

با API Resource خروجی JSON یکدست بدهید

برگرداندن مستقیم مدل‌های Eloquent ساختار پایگاه داده شما را در API عمومی نشت می‌دهد. API Resource یک جای واحد به شما می‌دهد تا دقیقاً تصمیم بگیرید کلاینت‌ها چه چیزی دریافت کنند.

class PostResource extends JsonResource
{
    public function toArray($request): array
    {
        return [
            'id'         => $this->id,
            'title'      => $this->title,
            'author'     => $this->user->name,
            'created_at' => $this->created_at->toIso8601String(),
        ];
    }
}

اعتبارسنجی را به Form Request بسپارید

به‌جای پر کردن کنترلرها با قوانین اعتبارسنجی، آن‌ها را در یک Form Request جدا بنویسید. کنترلرها کوتاه می‌مانند و قوانین قابل‌استفاده مجدد و تست‌پذیر می‌شوند.

class StorePostRequest extends FormRequest
{
    public function rules(): array
    {
        return [
            'title' => ['required', 'string', 'max:120'],
            'body'  => ['required', 'string'],
        ];
    }
}

قاعده سرانگشتی: اگر متد یک کنترلر از چند خط بیشتر شد، احتمالاً کاری انجام می‌دهد که جای دیگری باید باشد.

از روز اول API را نسخه‌بندی کنید

تغییر قرارداد یک API بدون نسخه‌بندی یعنی خراب کردن کلاینت‌هایی که شاید اصلاً نمی‌شناسید. یک پیشوند ساده در مسیرها کافی است تا برای تکامل API جا داشته باشید:

Route::prefix('v1')->group(function () {
    Route::apiResource('posts', PostController::class);
});

کدهای وضعیت و خطاها را یکدست نگه دارید

کلاینت باید بتواند بدون تجزیه یک جمله انسانی به خطا واکنش نشان دهد. مجموعه کوچکی از کدهای وضعیت انتخاب کنید، همه‌جا از آن‌ها استفاده کنید و خطاها را در یک قالب قابل‌پیش‌بینی برگردانید.

کد وضعیتزمان استفاده
