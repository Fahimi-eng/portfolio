Laravel REST API Best Practices I Wish I Knew Earlier

API resources, form requests, versioning and consistent errors: four habits that make a Laravel API easier to grow and easier to trust.

Return consistent JSON with API Resources

Returning Eloquent models directly leaks your database structure into your public API. API Resources give you a single place to decide exactly what clients receive.

class PostResource extends JsonResource
{
    public function toArray($request): array
    {
        return [
            'id'         => $this->id,
            'title'      => $this->title,
            'author'     => $this->user->name,
            'created_at' => $this->created_at->toIso8601String(),
        ];
    }
}

Validate with Form Requests

Instead of filling controllers with validation rules, move them into a dedicated Form Request. Controllers stay short, and the rules become reusable and easy to test.

class StorePostRequest extends FormRequest
{
    public function rules(): array
    {
        return [
            'title' => ['required', 'string', 'max:120'],
            'body'  => ['required', 'string'],
        ];
    }
}

Rule of thumb: if a controller method grows past a handful of lines, it is probably doing work that belongs somewhere else.

Version your API from day one

Changing an unversioned API means breaking clients you may not even know about. A simple route prefix is enough to give yourself room to evolve:

Route::prefix('v1')->group(function () {
    Route::apiResource('posts', PostController::class);
});

Use status codes and errors consistently

Clients should be able to react to an error without parsing a human sentence. Pick a small set of status codes, use them everywhere, and return errors in one predictable shape.

StatusWhen to use it
200 OKSuccessful read or update
201 CreatedA new resource was created
204 No ContentSuccessful delete
401 UnauthorizedMissing or invalid credentials
403 ForbiddenAuthenticated but not allowed
404 Not FoundThe resource does not exist
422 Unprocessable EntityValidation failed
429 Too Many RequestsRate limit reached

Warning: never return raw exception messages to clients in production. They expose internal details of your system.
